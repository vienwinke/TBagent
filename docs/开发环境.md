## 2. 数据库（直连，无需中继）

MySQL 8.4 与项目同在 WSL，`app_user@'%'` 直接可连：

```
DB_HOST=127.0.0.1
DB_PORT=3306          # WSL 内部直连
DB_USER=app_user
DB_NAME=treatbord
```

自检：

```bash
. .venv/bin/activate
python -c "from agent import executor; print(executor.health())"
# {'user': 'app_user@%', 'read_only': 1, 'max_execution_time_ms': 3000, ...}
```

> **为什么不再需要中继脚本？**
> 之前项目放在 Windows 盘、用 Windows 版 Python 连接时，MySQL 会把经 WSL2 端口转发进来的连接解析成
> `localhost`，而账号只有 `app_user@'%'`（没有 `@'localhost'`）→ `Access denied`。
> 现在 Python 跑在 WSL 内部，来源是 `127.0.0.1` → 匹配 `%` ✓。
> `scripts/wsl_db_relay.py` 保留作为「Windows 侧运行」时的备用方案（33306 → 3306）。

**本地全链路联调（Java → 边车 → MySQL）**：
```bash
# 1) 起边车（密钥要与 Java 侧一致）
SIDECAR_JWT_SECRET=<32字节密钥> SIDECAR_PORT=8080 python -m sidecar.app
# 2) 起 treatbord（注入内部 JWT 密钥与边车地址；.env.local 提供 MYSQL_*）
cd ../treatbord && set -a && . ./.env.local && set +a
TREATBORD_AI_SIDECAR_JWT_SECRET=<同一个密钥> \
TREATBORD_AI_SIDECAR_BASE_URL=http://127.0.0.1:8080 mvn -o spring-boot:run
# 3) 用真实登录 token 打问答（流式 / 非流式）
curl -N -X POST localhost:8081/api/ai/chat -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"s1","question":"我接取的任务里有多少已完成？","client_msg_id":"m1"}'
curl -s -X POST localhost:8081/api/ai/ask -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"session_id":"s1","question":"你好"}'
```
> 端到端事件序应为：`meta → scope → route → sql? → table? → chart? → delta → guard? → saved? → done`。
> 本地实测（2026-10-02）：真实数据问答答案「已完成数 = 2」正确返回，`saved` 带出 `message_id`，
> 会话列表/消息/反馈/登出即时失效全部通过。

**打开审计落库**（可选，默认关闭）：先确认表已建（treatbord 侧 Flyway 会自动执行 `V9__add_ai_tables.sql`），
再在 `.env` 设 `AUDIT_ENABLED=true`（生产建议另配 `AUDIT_DB_USER/PASSWORD`，只给 INSERT/SELECT）。
验证：问一句 → `SELECT * FROM ai_query_audit ORDER BY id DESC LIMIT 1;`；
或 `curl localhost:8080/readyz` 看 `audit_enabled` 与写入计数。

**成本与用量报表**（按用户 / 按天，从审计表聚合，只读）：
```bash

python scripts/cost_report.py --by day --days 30    # 按天
```

**嵌入所需的 `ai_*` 表**（会话/消息/审计/反馈/提示词版本）：`mysql -u <可写账号> -p treatbord < sql/ai_tables.sql`
> 幂等可重跑；脚本末尾附最小权限授权模板（审计表只给 INSERT/SELECT，只增不改）。
> ⚠️ 必须用**可写账号**执行 —— 边车问答链路用的只读账号建不了表。

**更正统的做法（拿到 MySQL root 后）**：`mysql -u root -p < sql/readonly_user.sql` 建 `agent_ro@localhost` 只读账号，

## 4.5 AI 边车（服务化形态，可选）

```bash
pip install -r requirements-sidecar.txt          # fastapi + uvicorn（Streamlit 演示不需要）
SIDECAR_JWT_SECRET=dev-secret python -m sidecar.app      # 默认只绑 127.0.0.1:8080

# 联调：用同一密钥签一个内部 JWT（treatbord 侧由 Java 签发，这里给的是等价物）
TOKEN=$(python -c "import time,sys; sys.path.insert(0,'.'); from sidecar import auth; \
  n=time.time(); print(auth.sign({'sub':'7','role':'USER','jti':'j1','iat':n,'exp':n+120,'aud':'ai-sidecar'}, 'dev-secret'))")
curl -N -X POST localhost:8080/v1/ai/chat -H "Authorization: Bearer $TOKEN" \
     -H 'Content-Type: application/json' -d '{"session_id":"s1","question":"我接了几个任务？"}'
```

**身份是硬要求**：没配 `SIDECAR_JWT_SECRET` 时 `/v1/ai/chat` 一律 **503**（fail-closed）；
伪造签名 / 过期 / 缺 token → **401**。本地偷懒可设 `SIDECAR_DEV_PRINCIPAL=7:USER`（配了密钥即失效）。
门槛与错误码见 [treatbord嵌入-接口契约.md](treatbord嵌入-接口契约.md) §2.1–§2.4。

## 4.6 本地跑 CI 的「MySQL 类型/DDL 子集」

CI 主门禁用 `data/snapshot.sqlite`（快、不需要服务），但 **sqlite 没有 Decimal、也不是 MySQL
方言** —— 这正是"类型类缺陷"的盲区。实测代价：金额列（`DECIMAL`）在边车序列化 SSE 帧时抛
`TypeError`、连接被掐，而上游只看到"边车不可达"，CI 却一直是绿的。

所以 CI 里另有一个 `mysql-types` 任务：起一个 **MySQL 8.4 空库** → 建 `ai_*` 表
（`sql/ai_tables.sql`）与**最小业务 fixture**（`sql/test_fixture.sql`：`task` + `notification`）
→ 跑这些文件：`test_audit` · `test_session` · `test_cost_report` · `test_sidecar_sessions` · `test_jsonable`。

本地等价复现（用你自己的 MySQL，库名任选；`TEST_DB_NAME` 决定测试写库去哪）：
```bash
mysql -u <可写账号> -p <库名> < sql/ai_tables.sql
mysql -u <可写账号> -p <库名> < sql/ai_feedback_updated_at.sql   # V10：当前 schema = V9 + V10
mysql -u <可写账号> -p <库名> < sql/ai_feedback_backfill_updated_at.sql  # V11：修正 V10 的历史行假阳性
mysql -u <可写账号> -p <库名> < sql/test_fixture.sql
DB_BACKEND=mysql DB_NAME=<库名> TEST_DB_NAME=<库名> AUDIT_ENABLED=true SESSION_ENABLED=true \
  python -m pytest tests/test_audit.py tests/test_session.py tests/test_cost_report.py \
    tests/test_sidecar_sessions.py tests/test_jsonable.py -q
```
> `sql/test_fixture.sql` **不是生产 schema**：只建子集真正会碰到的表。一旦有测试碰到别的表，
> CI 会红 —— 那是我们要的信号，而不是静默跳过。
> `test_eval_baseline` 的 3 条用例需要**完整业务库**（跑参考 SQL），不在该子集内，
> 请连真实 MySQL 在本机验证。

## 6. 切换大模型平台（当前：Command Code Provider API）

项目用 **OpenAI 兼容协议**（`openai` SDK），所以换平台**只改 `.env` 两三行，代码一行不动**。

### 当前配置（Command Code）

```ini
LLM_API_KEY=<到 https://commandcode.ai/studio/provider 生成>
LLM_BASE_URL=https://api.commandcode.ai/provider/v1
LLM_MODEL=deepseek-chat
```

- Command Code 同时兼容 **OpenAI / Anthropic** 格式，本项目用其中的 **Chat Completions**（`POST /provider/v1/chat/completions`）
- 该 base_url 下还有 `responses`、`messages`、`models` 三个端点（`GET /provider/v1/models` 可列出可用模型）
- 计费：Provider 套餐 **$15/月 + $1.01 手续费**，之后按底层 API 费率**无加价**按量计费，额度不过期

### 第一步：探测端点（填完 key 就跑）

```bash
cd ~/Project/agent && . .venv/bin/activate
python scripts/probe_endpoint.py
```
会输出：
1. 鉴权是否通过
2. **可用模型列表**（从里面挑一个填进 `LLM_MODEL`）
3. 最小对话调用的返回内容 + token 用量 + 延迟 + 本次成本估算
4. **是否支持 `response_format={"type":"json_object"}`**（本项目结构化输出依赖它；不支持会自动降级为正则提取 JSON ✓）

指定其它模型/端点：
```bash
python scripts/probe_endpoint.py --model <模型名>
```
