# 开发环境说明（WSL 原生）

项目位置：`~/Project/agent`（WSL）＝ Windows 侧 `\\wsl.localhost\Ubuntu\home\KeYa\Project\agent`

## 1. Python 环境

```bash
cd ~/Project/agent
python3 -m venv .venv                 # 已创建（Python 3.14.4）
. .venv/bin/activate
pip install -r requirements.txt       # 轻依赖已装；向量后端见第 3 节
```

> 该 Python 版本（3.14）的 numpy / pandas / pyarrow 轮子已确认可用（cp314）。
> 但 **torch 目前没有 3.14 轮子** → 若要用本地 BGE 向量检索，见第 3 节的两种办法。

## 2. 数据库（直连，无需中继）

MySQL 8.4 与项目同在 WSL，`app_user@'%'` 直接可连：

```
DB_HOST=127.0.0.1
DB_PORT=3306          # WSL 内部直连
DB_USER=app_user
DB_NAME=treatbord
```

自检：

```bash
. .venv/bin/activate
python -c "from agent import executor; print(executor.health())"
# {'user': 'app_user@%', 'read_only': 1, 'max_execution_time_ms': 3000, ...}
```

> **为什么不再需要中继脚本？**
> 之前项目放在 Windows 盘、用 Windows 版 Python 连接时，MySQL 会把经 WSL2 端口转发进来的连接解析成
> `localhost`，而账号只有 `app_user@'%'`（没有 `@'localhost'`）→ `Access denied`。
> 现在 Python 跑在 WSL 内部，来源是 `127.0.0.1` → 匹配 `%` ✓。
> `scripts/wsl_db_relay.py` 保留作为「Windows 侧运行」时的备用方案（33306 → 3306）。

**更正统的做法（拿到 MySQL root 后）**：`mysql -u root -p < sql/readonly_user.sql` 建 `agent_ro@localhost` 只读账号，
再把 `.env` 的 `DB_USER/DB_PASSWORD` 换过去（最小权限）。

## 3. 向量检索（可选）

默认 `EMBED_BACKEND=bm25`：零依赖，实测 Schema Top-5 召回 **12/12 = 100%**，够用。

若要语义检索（BGE-small-zh + FAISS），二选一：

```bash
# 方案 A：用 uv 装一个带 torch 轮子的 Python 3.12（无需 root）
curl -LsSf https://astral.sh/uv/install.sh | sh
uv venv --python 3.12 .venv312
uv pip install --python .venv312/bin/python torch --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv312/bin/python sentence-transformers faiss-cpu

# 方案 B：保持 3.14，等 torch 支持；或改用云端 Embedding API
```
然后 `.env` 改 `EMBED_BACKEND=local` 并重建索引。
