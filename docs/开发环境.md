# 开发环境说明

## 1. Python 环境（Windows 侧）

```powershell
cd E:\project\agent
python -m venv .venv                      # 已创建（Python 3.13.14）
.venv\Scripts\activate
pip install -r requirements.txt           # 已安装轻依赖；torch/faiss 见第 4 节
```

> 项目放在 Windows 盘（`E:\project\agent`，WSL 里对应 `/mnt/e/project/agent`），
> **Python 在 Windows 侧运行**（3.13 对 torch/faiss 轮子支持最好）。

## 2. `.env`（不入 git，权限 600）

| 键 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY` | 大模型 Key（**待填**）。platform.deepseek.com → API Keys |

| `EMBED_BACKEND` | `bm25`（默认，零依赖）/ `local`（BGE 向量）/ `api` |

## 3. ⚠️ 数据库连通性：为什么需要一个 WSL 中继

**现状**：treatbord 的 MySQL 跑在 WSL2，只监听 `127.0.0.1:3306`；账号只有 `app_user@'%'`（**没有 `@'localhost'`**）。
Windows 侧经 WSL2 端口转发连进去时，MySQL 把来源解析成 `localhost` → 匹配不上 → `Access denied`。

**解法（零 root 权限）**：在 WSL 里跑一个纯标准库 TCP 中继，把 `33306` 转发到 `127.0.0.1:3306`；
Windows 侧连 `127.0.0.1:33306`，对 MySQL 而言连接来自 WSL 内部，路径与 `mysql` CLI 完全一致。

```bash
# 在 WSL 里执行（保持常驻）
nohup python3 /mnt/e/project/agent/scripts/wsl_db_relay.py > /tmp/db_relay.log 2>&1 &
ss -lnt | grep 33306          # 应看到 0.0.0.0:33306
```
对应 `.env`：`DB_HOST=127.0.0.1`、`DB_PORT=33306`

**更正统的替代方案（拿到 MySQL root 后）**：直接建一个能匹配 `localhost` 的只读账号，然后改回 `3306`：
```bash
mysql -u root -p < sql/readonly_user.sql     # 内含 agent_ro@localhost / @% 的授权
```

## 4. 可选：向量检索（Embedding）

默认 `EMBED_BACKEND=bm25`（零依赖，实测 Schema Top-5 召回 **12/12 = 100%**）。
若要语义检索：
```powershell
pip install torch --index-url https://download.pytorch.org/whl/cpu   # 先装 CPU 版 torch（~200MB）
pip install sentence-transformers faiss-cpu
# 然后 .env 改 EMBED_BACKEND=local，重新 python -m agent.schema_index --build
```
BGE 模型权重（`BAAI/bge-small-zh-v1.5`，约 100MB）首次运行自动下载。
